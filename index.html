/ about

I started out in physics, planning on astrophysics, and picked up a second degree in data science at IIT Madras along the way. The two turned out to be the same job: deciding whether a result is real.

At WorldQuant, a trading signal only counts if it holds up on data it has never seen. In LIGO's detectors, a burst of noise can look exactly like a gravitational wave. And a repaired notebook can run perfectly and still print the wrong numbers. A lot of what I build is about telling those apart.

Most of my work runs on Python and SQL, with PyTorch for deep learning, and statistical testing underneath all of it.

So what's a Sharpe ratio?

A measure of return relative to volatility: higher generally means more return for each unit of risk.

Physics-informed machine learning for electrochemical sensors

This project explores how to make machine learning reliable for electrochemical sensors, the technology behind glucose meters and point-of-care diagnostics.

Research questions

  1. Learning from little data. Sensor experiments are slow and expensive, so datasets are small. Physics acts as a constraint, so models need far fewer measurements to generalise.
  2. Holding up across setups. Sensors vary between production batches, instruments and labs, and drift as they age. The aim is models that stay reliable when data comes from different setups, where standard ML quietly breaks down.
  3. Learning without sharing data. Medical and industrial data often can't leave the institution that collected it, so models need to learn across sites while the raw data stays private.

Alongside the project, these are the questions in the field that have my attention.

Why physics-informed networks fail, and what fixes them

A physics-informed neural network (PINN) combines observations with governing physical laws, typically through a loss that includes data or boundary conditions alongside the residual of a governing PDE evaluated at collocation points. The premise is intuitive: let the underlying physics constrain what the model can learn when data is thin. Whether that actually translates to more reliable generalization in practice is a much more nuanced question.

The slider captures the central tension. Dial the physics weight down, and the model can fit the observations while paying less attention to the governing equation. Dial it up too high, and the PDE residual can dominate the optimization at the expense of the observations.

Illustration, not measured results. Dots indicate observations; the shaded band contains none.

Three things make PINNs particularly interesting to me:

  1. Loss balancing: The data and physics terms can have very different scales and gradient behaviour, making fixed weights difficult to choose. This is why adaptive schemes that rebalance the terms using gradient statistics or neural tangent kernel (NTK) based approaches remain an active area of research.
  2. Spectral bias: Neural networks tend to learn low-frequency structure before higher-frequency detail. That can make sharp fronts and multi-scale behaviour difficult to capture. Fourier features and domain decomposition are among the approaches researchers use to address these difficulties.
  3. Collocation points: Where the model is asked to satisfy the physics matters. Uniform sampling can spend computation in regions that are already easy to approximate, while residual-based adaptive sampling puts more points where the PDE residual is large or the solution is difficult to capture. How to allocate those points efficiently is an important part of making PINNs work well when data is scarce.

When the Issue Is Missing

Turns out ‘Fixes #3417’ is not a specification

Coding agents built on small open models often hit a plateau that people blame on the model. I showed that in this competition, much of that plateau comes from the tasks themselves: a third of task statements are just a pull-request title and a link the offline agent can't open. Giving the unchanged agent the linked issue let it solve tasks it had never solved, while another task's issue didn't help.

Key results

  1. 0 → 16 of 27. Tasks four agent designs never solved, once the unchanged agent had a full specification.
  2. 8 vs 1. Tasks solved with the task's own linked issue against another task's issue, in a pre-registered test.
  3. 32% vs 0–2.4%. Task statements that just defer to a link, here against ten widely used coding benchmarks.
Read the paper ↗

How I tested it

  • Built and evaluated a coding agent: Gemma 4 31B (4-bit) on vLLM with Google's Agent Development Kit, on 4 NVIDIA L4 GPUs.
  • Ran 11 local evaluation runs (594 task attempts) and made 24 leaderboard submissions.
  • Pre-registered the analysis plan, posting its SHA-256 hash in the forum before seeing any result, then ran replications, placebo controls and a hidden-tests arm.
  • Wrote a rule that detects these "deferred" statements automatically and applied it to about 54,000 tasks from ten public datasets, including SWE-bench and SWE-Gym.
  • Showed why the leaderboard hid all this: identical submissions scored 6 to 11 of 58, and published top scores came out 3 to 5 tasks lower when the same files were scored again.
  • Released the data and a notebook that recomputes and checks every reported number.
